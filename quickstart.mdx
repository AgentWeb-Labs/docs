This guide walks you through connecting AgentWeb to the AI agent you already use, checking whether your target website and action are supported, authenticating, and running your first verified task.

<Warning>
  Never place passwords, raw card numbers, or unrestricted credentials in a tool request. AgentWeb vaults credentials through a hosted sign-in ceremony so sensitive values never enter the conversation.
</Warning>

<Steps>
  <Step title="Add the MCP server">
    AgentWeb exposes a Streamable HTTP MCP server at `https://mcp.agentweb.us/mcp`.

    If you use **Claude Code**, run:

    ```bash
    claude mcp add agentweb --transport http https://mcp.agentweb.us/mcp
    ```

    If you use any other MCP client — Codex, Cursor, ChatGPT, or another compatible client — add the same URL as a remote Streamable HTTP server in your client's MCP settings. No other configuration is required at this stage.
  </Step>

  <Step title="Explore without an account">
    You can inspect AgentWeb coverage and read public page content before creating an account. Two tools work anonymously — no API key required:

    - **`read_page`** — retrieves accessible page content as clean text, links, forms, and metadata for a given URL.
    - **`discover`** — inspects which Action Maps are available for a target domain and what authentication the site requires.

    Both tools are also available via REST: `GET /api/read` and `GET /api/discover`.

    <Note>
      Coverage is action-specific — a mapped domain does not mean every possible task on that site is supported. Always use `discover` before promising completion to the user.
    </Note>

    Run `discover` against your target domain to confirm the action you need exists before proceeding to account creation.
  </Step>

  <Step title="Create your AgentWeb account">
    Before your agent can list or execute actions, you need an `aw_` API key. You receive **100 free credits** when you sign up. The preferred flow uses a **claim link** so you can review the [Terms](https://www.agentweb.us/terms) and [Privacy Policy](https://www.agentweb.us/privacy) and sign in through a hosted page — no password enters the conversation.

    **Preferred: claim-link flow**

    1. Ask your agent to call `agentweb_start_claim_link_signup`.
    2. Your agent returns a `verification_uri_complete` URL. Open it in your browser.
    3. Review the Terms and Privacy Policy, then sign in.
    4. Your agent polls `agentweb_poll_claim_link_signup` with the `deviceCode` returned in step 1 and receives the API key once sign-in is complete.

    **Fallback: email-code flow**

    If the claim-link flow is unavailable, use the two-step email-code flow:

    1. Call `agentweb_start_api_key_signup` with your email address.
    2. Enter the verification code sent to your inbox by calling `agentweb_complete_api_key_signup`.

    **Reconnect with your key**

    Once you have your key, instruct your agent to reconnect using:

    ```http
    Authorization: Bearer aw_<key>
    ```

    Your agent now has authenticated access to the full AgentWeb tool set.
  </Step>

  <Step title="List available actions">
    After authentication, call `list_actions` to retrieve the current catalog of supported actions. Each action entry includes:

    - Required input fields and their types
    - Account connection requirements
    - Possible outcome states and verification behavior

    Review the action's requirements before executing, especially whether it needs a connected account on the target site.
  </Step>

  <Step title="Connect a target-site account (if required)">
    Some actions require your account on the target website — for example, to place an order on a merchant that needs you to be signed in. Before executing, check whether a connection is already in place:

    - Call `agentweb_auth_status` to check your AgentWeb authentication state.
    - Call `agentweb_connection_status` to check whether a required target-site account is already connected.

    If a connection is missing or expired, start the connection flow:

    1. Call `agentweb_start_connection`. AgentWeb returns a connection URL.
    2. Open the URL in your browser and complete the sign-in on the target site.
    3. Your agent polls `agentweb_poll_connection` until the connection status is ready.

    Once the connection is confirmed, the action can proceed. AgentWeb vaults the credentials — they are never passed back to the agent.
  </Step>

  <Step title="Execute and verify">
    With authentication and any required connections in place, call `execute` with the selected Action Map name and your declared inputs. The exact field names come from the action's schema returned by `list_actions`.

    ```json
    {
      "action": "<action_id>",
      "inputs": {
        "<field_name>": "<value>"
      }
    }
    ```

    For readiness checks before execution, you can also call `POST /api/readiness/scan` with a target URL to confirm a site is reachable and mapped.

    AgentWeb runs the action as a tracked job and returns one of the following:

    - **Verified receipt** — structured confirmation with identifiers from the system of record
    - **Booking reference or submitted record** — artifact tied to the real site outcome
    - **Structured failure** — explicit failure state with the reason and any recovery steps

    Treat the returned status and verification artifact as the source of truth. Never infer completion only because a request was accepted. If the job returns a pending or ambiguous state, wait for the next update rather than assuming success.
  </Step>
</Steps>
