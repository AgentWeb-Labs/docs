The AgentWeb MCP server at `https://mcp.agentweb.us/mcp` exposes tools across four categories: core execution, account and connection management, and installation and billing. The live manifest at `/.well-known/mcp/tools.json` is always the authoritative source for current tool names, signatures, and authentication requirements.

## Core execution tools

These tools let your agent read pages, discover what AgentWeb supports for a domain, and run mapped actions. `read_page` and `discover` work without authentication; `list_actions` and `execute` require an `aw_` API key.

<Accordion title="read_page — Retrieve structured page content">
  **Description:** Retrieves accessible content from a URL as structured text, links, forms, and metadata. No authentication is required, so you can call this tool before your agent has an AgentWeb account.

  **Auth required:** No

  **Key input:**

  <ParamField body="url" type="string" required>
    The fully-qualified URL of the page to read.
  </ParamField>

  **Returns:** Structured page content including visible text, navigation links, form fields, and page metadata.
</Accordion>

<Accordion title="discover — Inspect AgentWeb coverage for a domain">
  **Description:** Inspects AgentWeb coverage and entry points for a target domain. Use this tool to understand what Action Maps exist for a site before committing to authentication and execution.

  **Auth required:** No

  **Key input:**

  <ParamField body="url" type="string" required>
    The domain or page URL to inspect.
  </ParamField>

  **Returns:** Available Action Maps for the domain, authentication requirements for each action, and overall coverage status.
</Accordion>

<Accordion title="list_actions — List all mapped actions">
  **Description:** Lists every Action Map available to your authenticated AgentWeb account. You can filter by domain to narrow results.

  **Auth required:** Yes (`aw_` key)

  **Key input:**

  <ParamField body="domain" type="string">
    Optional domain filter. Omit to return all available actions across all covered sites.
  </ParamField>

  **Returns:** An array of action contracts, each containing the action name, required inputs, auth requirements, and expected outcomes.
</Accordion>

<Accordion title="execute — Run an Action Map">
  **Description:** Runs a selected Action Map with the inputs you provide. Always confirm consequential inputs with the user before calling this tool, and call it only once per user-approved action.

  **Auth required:** Yes (`aw_` key)

  **Key inputs:**

  <ParamField body="action" type="string" required>
    The action name as returned by `list_actions`.
  </ParamField>

  <ParamField body="inputs" type="object" required>
    An object of key-value pairs matching the action's declared input schema.
  </ParamField>

  **Returns:** A structured result containing a status (`completed`, `pending`, or `failed`), a verification artifact with evidence and signature metadata, a receipt, or a failure artifact with a `failure_class`.
</Accordion>

## Account and connection tools

These tools handle AgentWeb account creation, API key provisioning, and connecting target-site accounts. The claim-link flow is preferred — it produces a verified `aw_` key in a single human sign-in step.

<Accordion title="agentweb_start_claim_link_signup — Start account creation (preferred)">
  **Description:** Initiates the preferred one-link AgentWeb account creation flow. Call this first when setting up a new account. Always show the human the [Terms](https://www.agentweb.us/terms) and [Privacy Policy](https://www.agentweb.us/privacy) before starting.

  **Auth required:** No

  **Returns:** A `verification_uri_complete` link to show the human, and a `deviceCode` to use when polling.

  <Tip>
    Show only `verification_uri_complete` to the user — do not display the raw `deviceCode`.
  </Tip>
</Accordion>

<Accordion title="agentweb_poll_claim_link_signup — Poll for account completion">
  **Description:** Polls the claim-link flow while the user completes sign-in. Keep polling until you receive a final result or an error.

  **Auth required:** No

  **Key input:**

  <ParamField body="deviceCode" type="string" required>
    The `deviceCode` returned by `agentweb_start_claim_link_signup`.
  </ParamField>

  **Returns:** On success — the `aw_` API key, a `welcome_message` to send in the conversation, and a setup command. Reconnect to the MCP server with the returned key.
</Accordion>

<Accordion title="agentweb_start_api_key_signup — Start email-code signup (fallback)">
  **Description:** Initiates email-code-based account creation when the claim-link flow is not available. A verification code is sent to the provided email address.

  **Auth required:** No

  **Returns:** Confirmation that a verification code has been dispatched to the supplied email address.
</Accordion>

<Accordion title="agentweb_complete_api_key_signup — Complete email-code signup">
  **Description:** Completes the email-code signup flow by submitting the verification code the user received.

  **Auth required:** No

  **Key input:**

  <ParamField body="code" type="string" required>
    The verification code sent to the user's email address.
  </ParamField>

  **Returns:** The provisioned `aw_` API key.
</Accordion>

<Accordion title="agentweb_start_connection — Connect a target-site account">
  **Description:** Starts the flow for connecting an external account (for example, a provider site) so that an Action Map can access it. Call this when `list_actions` indicates a connection is required.

  **Auth required:** Yes (`aw_` key)

  **Returns:** A `connect_url` to open in the user's browser so they can authorize the connection.
</Accordion>

<Accordion title="agentweb_poll_connection — Poll connection status">
  **Description:** Polls the target-site connection until it reaches a final state. Stop if the connection expires, is refused, or is attached to the wrong account.

  **Auth required:** Yes (`aw_` key)

  **Returns:** `connected: true` or `false`, plus the current connection state.
</Accordion>

<Accordion title="agentweb_auth_status — Check AgentWeb auth state">
  **Description:** Returns the current authentication state of your AgentWeb account. Useful for confirming that your `aw_` key is valid before executing a workflow.

  **Auth required:** Yes (`aw_` key)

  **Returns:** The current AgentWeb account auth state.
</Accordion>

<Accordion title="agentweb_connection_status — Check target-site connection state">
  **Description:** Returns the current connection state for a specific target site. Call this before `execute` to verify the required external account is still connected.

  **Auth required:** Yes (`aw_` key)

  **Returns:** The current target-site connection state.
</Accordion>

## Installation and billing tools

These tools walk through scanning a business URL, generating an install plan, pricing setup, checkout, and deployment verification. They are typically used once during onboarding.

<Accordion title="agentweb_scan_business — Scan a company URL for agent readiness">
  **Description:** Audits a company URL to determine how ready it is to support AI agent workflows — covering discoverability, understandability, integratability, and usability.

  **Auth required:** No

  **Returns:** An agent-readiness report with discoverability score, action candidates, and identified gaps.
</Accordion>

<Accordion title="agentweb_install_agentweb — Generate an install plan">
  **Description:** Generates a full Agent Tool install plan including PR files, a pricing package, Dodo payment authority requirements, and a verification checklist.

  **Auth required:** No

  **Returns:** Install plan, PR-ready files, pricing package, and a step-by-step verification checklist.
</Accordion>

<Accordion title="agentweb_price_setup — Return setup package and payment requirements">
  **Description:** Returns the setup package and any payment authority requirements needed before checkout can proceed.

  **Auth required:** No

  **Returns:** Setup package details and payment authority requirements.
</Accordion>

<Accordion title="agentweb_create_checkout_session — Create a Dodo hosted checkout">
  **Description:** Creates a Dodo hosted checkout session for Pro or Max account plans and returns a handoff URL. Open that URL in the customer's browser and let checkout finish there.

  **Auth required:** No

  **Returns:** A handoff URL that signs the customer in and starts the Dodo hosted checkout for the chosen plan.

  <Warning>
    Checkout success is not proof of credit fulfillment. Credits are only granted after AgentWeb's Dodo webhook verification completes. See the [Webhooks reference](/reference/webhooks) for details.
  </Warning>
</Accordion>

<Accordion title="agentweb_verify_install — Verify deployed agent-facing surfaces">
  **Description:** Verifies that the discovery files, Action Maps, and other agent-facing surfaces deployed during installation are reachable and correct.

  **Auth required:** No

  **Returns:** A proof artifact confirming which surfaces are live and correctly configured.
</Accordion>

<Note>
  Tool names and authentication requirements may change between releases. Always inspect the live manifest at `https://mcp.agentweb.us/.well-known/mcp/tools.json` rather than hardcoding an assumed catalog.
</Note>
