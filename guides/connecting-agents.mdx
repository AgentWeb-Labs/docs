AgentWeb exposes a Streamable HTTP MCP server at `https://mcp.agentweb.us/mcp`. Any MCP-compatible agent — including Claude Code, Cursor, Windsurf, ChatGPT, Codex, Goose, and generic MCP clients — can connect to it in a single step and immediately start reading pages, discovering coverage, and executing mapped actions.

## Add the MCP server

Choose your client and follow the instructions below.

<Tabs>
  <Tab title="Claude Code">
    Run this command in your terminal to register AgentWeb as a named MCP server:

    ```bash
    claude mcp add agentweb --transport http https://mcp.agentweb.us/mcp
    ```

    Claude Code will make the server available to your agent automatically on the next session start.
  </Tab>
  <Tab title="Cursor">
    Open Cursor's MCP settings and add a new **Streamable HTTP** MCP server with the following URL:

    ```
    https://mcp.agentweb.us/mcp
    ```

    Save the entry and reload Cursor to activate the connection.
  </Tab>
  <Tab title="Windsurf">
    Open Windsurf's settings and navigate to the MCP server configuration panel. Add a new **Streamable HTTP** MCP server pointing to:

    ```
    https://mcp.agentweb.us/mcp
    ```

    Restart Windsurf after saving so the server is available in your next session.
  </Tab>
  <Tab title="ChatGPT">
    In ChatGPT's settings, open the **Connectors** or **MCP** section and add a new **Streamable HTTP** MCP server with the following URL:

    ```
    https://mcp.agentweb.us/mcp
    ```

    Save the entry and start a new conversation to activate the connection.
  </Tab>
  <Tab title="Codex">
    In your Codex environment configuration, add a remote **Streamable HTTP** MCP server entry pointing to:

    ```
    https://mcp.agentweb.us/mcp
    ```

    Consult the Codex documentation for the exact configuration key. No local binary is required.
  </Tab>
  <Tab title="Goose / Other">
    In your MCP client's configuration file or settings UI, add a new **remote Streamable HTTP** server entry:

    ```
    https://mcp.agentweb.us/mcp
    ```

    Consult your client's documentation for the exact configuration key names. No local process or binary is required — the server runs remotely.
  </Tab>
</Tabs>

## After connecting the server

<Steps>
  <Step title="Explore anonymously">
    Ask your agent to call `discover` with a target domain to inspect AgentWeb's coverage, or call `read_page` with any URL to retrieve its accessible content as structured text. Neither tool requires an account.
  </Step>
  <Step title="Create your account">
    When you are ready to list or execute actions, create an AgentWeb account. Before starting, your agent will show you the [Terms of Service](https://www.agentweb.us/terms) and [Privacy Policy](https://www.agentweb.us/privacy) for your review.

    **Preferred — claim-link flow:**

    1. Your agent calls `agentweb_start_claim_link_signup`.
    2. Your agent shows you only the returned `verification_uri_complete` link.
    3. You open the link and sign in once in your browser.
    4. Your agent polls `agentweb_poll_claim_link_signup` with the returned `deviceCode` while you sign in.
    5. The completed poll returns your `aw_` API key along with a `welcome_message`.

    **Fallback — email-code flow:**

    If the claim-link flow is unavailable, your agent can use the email-code fallback instead:

    1. Your agent calls `agentweb_start_api_key_signup` with your email address.
    2. You receive a verification code by email.
    3. Your agent calls `agentweb_complete_api_key_signup` with the code to receive your `aw_` API key.
  </Step>
  <Step title="Reconnect with your key">
    After the poll completes, your agent reconnects to the MCP server using your key for all subsequent calls:

    ```
    Authorization: Bearer aw_<key>
    ```

    Keep this key out of source control, screenshots, and public logs.
  </Step>
  <Step title="List available actions">
    Your agent calls `list_actions` with a target domain to see the mapped actions AgentWeb supports for that site, along with each action's required fields and account requirements.
  </Step>
  <Step title="Execute a task">
    Your agent calls `execute` with the selected action and its declared inputs. Treat the returned status, verification artifact, or structured failure as the source of truth — never infer completion from a request being accepted alone.
  </Step>
</Steps>

<Note>
  Public discovery files are also available at [`/llms.txt`](https://www.agentweb.us/llms.txt), [`/llms-full.txt`](https://www.agentweb.us/llms-full.txt), [`/.well-known/mcp/tools.json`](https://www.agentweb.us/.well-known/mcp/tools.json), and [`/openapi.json`](https://www.agentweb.us/openapi.json). Integrations should inspect the live tool manifest rather than assuming a fixed catalog.
</Note>

<Warning>
  Never place passwords, raw card numbers, or unrestricted credentials in a tool request.
</Warning>
